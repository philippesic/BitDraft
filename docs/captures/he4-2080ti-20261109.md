# HE4 teacher capture on DESKTOP-T4JKGJB

User-authorized capture only through November 9, 2026 noon Pacific (20:00 UTC).
No training and no RTX 5080 GPU use. The source model and CPU-readable source
assets were copied from the 5080. vLLM files/environments are untouched.

Work directory: `/home/philip/he4-capture-2080ti`.
Live state: `status.json`; authenticated dataset index: `manifest.json` plus
`manifest.sha256`; immutable per-sequence proofs: `captures/shard-*/*/capture/verification.json`.
The terminal `completion.json` is sent to the user-authorized webhook only when
the actual campaign stops. `webhook-receipt.json` records delivery.

Initial GPU check: idle, no compute processes; no wait for another project.
Initial disk available: approximately 728 GiB. Reserve 30 GiB. Eight F32 taps
cost 81,920 bytes per input token. Initial 4,492 eligible prompt estimates are
about 146 GiB features; exact current-tokenizer counts govern disk admission.
Ten thousand recordings at the same estimated length cost about 329 GiB.
These are planning estimates, not measured capture totals.

The modern bank has 192 reserved TRAIN groups. Exclude the 16 groups already
captured in the component campaign; prioritize the other 176. Then use the
historical DSpark optimizer selector (TRAIN roles only), excluding evaluation
identities and duplicate groups. Current conservative admission retains 4,316
historical records and rejects 5,540 collisions/duplicates. No historical
features, token IDs, or labels are reused. All texts are rendered and tokenized
again with the hash-pinned Qwen3.5 model. After this pool, deterministic authored
math, dialogue, instructions, structured output, translation, editing, planning,
and classification prompts extend the set until the deadline or disk limit.

Exclusions include opaque dev/final/sealed partition indexes, historical
pilot/development/matrix inventories, both modern consumed confirmation sets,
consumed-natural-inputs, precision and component heldout24 consumption identities,
and the original modern development identities. Held-out answers are not used.
`exclusions.json` records identities and source hashes; `prompt-pool.json` records
admission, prior 16 names, and rejected candidates. This conservative filter
may discard eligible prompts; it never relaxes exclusions to increase counts.

The retained 5080 binaries require GLIBC 2.43 and cannot load here. Build the
retained runtime locally using the existing CUDA 12.8 toolchain (read only),
SM75, and the quant4group GGML source commit recorded in runtime-receipt.json.
This preserves consistent32 dispatch. Native labels are hardware-specific;
no cross-GPU numerical identity is claimed.

Contract: taps [2,6,10,14,18,22,26,30], zero-based pre-block input for every input
token; F32 feature files; KV F16; consistent32; native raw greedy continuation,
at most 128 labels. The first EOG can be a label; it is never consumed and no
post-EOG labels are created. All native hard labels must equal full-logit argmax.
Full logits are hashed and deleted after successful verification. Failed or
unverified directories never enter the manifest. Unique positions count sequence
identity plus token position, not unique vocabulary IDs. A sequence with n labels
has max(0,n-14) overlapping length-15 windows at stride one.

Later trainer: verify manifest SHA, then each referenced receipt and file hash.
Each record supplies little-endian F32 [tokens,2560] layer files, int32 inputs,
int32 hard labels, and int32 label_positions mapping labels to feature rows.
Read windows as consecutive 15-label slices; stop at the retained label boundary.
No KL or distillation payload is required. This work makes no promotion claim.

Launch after successful native smoke: `venv/bin/python project/scripts/he4_capture/run.py`.
The process uses only CUDA_VISIBLE_DEVICES=0 on this single-2080 machine.

The live campaign is running in a managed exec session. `process-evidence.json`
records its process/session identity. `campaign.pid` identifies only this run.
The first audited checkpoint contains 16 sequences, 1,824 windows, and 2,048
unique label positions. Sample hashes, tensor shapes, EOG masks, and manifest
counts passed. Both code and reasoning appeared in that checkpoint; prose is
queued in the same bank. `audit.py manifest.json` can independently check later
checkpoints while capture continues. Never signal completion merely because the
interactive agent hands back; the runner owns the terminal webhook.
