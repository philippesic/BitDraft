## Quality gates before interpretation

The oracle must see only independent case parameters/private tests plus the submitted content, with no arm identity or target answer. Send only each case's prompt to the model. Run every case's positive control and at least two distinct semantic negative controls through the same pinned judge before inference: one plausible wrong answer and one boundary/omission/unsupported-fact case. Wrong format/duplicate JSON fields alone are insufficient negative controls. Preserve the control outputs and require all controls behave correctly; otherwise the quality evaluator is unvalidated and the run is inconclusive.

Reuse `quality_judge.judge` directly for new JSON/Python case dictionaries; its Python tests check inputs remain unchanged. Restrict new functions to the judge's supported one-argument AST/builtins. Do not weaken that contract after seeing outputs. The grounded checks measure factual extraction/constraint following, not arbitrary prose style or broad human preference; report that limit. Record target-only quality score, each arm's score, case failures and oracle reasons. Exact target parity does **not** prove answers are correct: if the target fails an oracle, all matching arms may fail it too. Keep such failures in the denominator and explain them; do not replace questions. A preserved-quality claim requires no candidate regression plus the frozen independent quality requirements, with observed target limitations disclosed.
