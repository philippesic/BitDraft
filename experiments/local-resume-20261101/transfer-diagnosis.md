## Ranked discriminating experiments for root

1. **Replay actual histories and time their components before choosing a new objective.** On development requests capture accepted/rejected boundaries, target features/logits, draft cache/state, positions, masks, predecessor tokens and rollback. Pair fresh/parent/control on identical states: teacher-forced labels, free-running draft, and exact live-history replay. Stratify by depth, domain, rejection history and prompt length. Measure head/body/verifier/cache/synchronization separately with a diagnostic profiler; repeat full requests without profiling. If reset replay succeeds but live-history replay fails, isolate history/state handling before training. If both agree yet fail on newly visited states, prioritize coverage. For modern Qwen3.5 separately compare quantized-target batch/chunking and recurrent-state restoration across runtime variants; require identical accepted output IDs and independent answer quality. Historical Markov history is not proof of a Qwen3.5 recurrent-state bug.
2. **Test coverage against objective with matched exposure and initialization.** Native serving-history data versus existing fixed windows, crossed with existing loss versus first-error/accepted-prefix-weighted loss. Balance ordinary occupancy with difficult rejection states; split by original group ancestry before capture. Weight prose and early-depth failure by measured wasted rounds, not simply by label count. Keep a soft-logit/native teacher distillation arm where it distinguishes margin calibration from argmax fitting. Improvement only from new data supports coverage; improvement from objective at fixed data supports objective mismatch. Track full-request accepted tokens/round and time alongside prefix survival. Maintain fresh and resumed ancestry separately; avoid confounding diversity with different update exposure.
3. **Reduce measured head/runtime cost after component attribution.** Compare existing head with precision/layout/fusion or a trained cheaper head while holding body and teacher fixed. Admission requires candidate token/ranking fidelity and live acceptance; a shortlist must not silently alter verifier semantics. Test adaptive draft depth against fixed D5 on development, including no-draft fallback when expected saved verification work is below draft cost. Fewer accepted tokens can still win if total request time falls; higher acceptance can still lose if head cost rises.
4. **Capacity changes only after separating data and cost.** Compare body depth/width or recurrent/history encoding at matched data and declared compute exposure, selecting on development full-request benefit and checking whether failure remains concentrated at first token versus later survival. Preserve original checkpoints. Continue useful training based on transfer curves and marginal gains, with no invented GPU-hour cap or candidate-count limit.

For every experiment freeze target/verifier precision, hardware, runtime pins, inputs, cache policy, output limits and controls. Use paired alternating repeated full requests, report variability and domain effects, and retain a final untouched group-level confirmation. Q4_0 EAGLE remains the primary project baseline; retain same-family Q4_K_M and target-only controls where needed. Numeric gates should address label/ranking/gradient or trajectory changes; do not block native-data training solely on cross-backend floating-point drift. Revalidate after runtime changes.
